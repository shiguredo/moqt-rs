# 音声 playout の比較見直し

2026-10-20 に「qmux 経由で音声がプチプチする」という報告を受け、moqt-rs の playout を
moqt-js の再生実装と比較して見直した記録である。原因の整理と、実施した対策の根拠を残す。
数値は特に断らない限り moqt-js 側の実リレー計測 (`docs/AUDIO_PLAYOUT_GAPS_AND_TAIL.md`) に
よる。moqt-rs の実機計測はまだ行っていない。

## 結論

- moqt-js の playout の純粋な計算（時間圧縮、補間、遅延推定、閉ループ、追いつき、時間軸）は
  行単位で移植されており、数式・定数・境界に聴感差を生む差異は無い。
- プチプチの主因は移植ミスではなく、再生方針と出力経路にある。moqt-js 側でも同じ問題
  （補間しなかった隙間が境界の段差になる、予約できない隙間がアンダーランになる）が実測で
  確認されており、moqt-rs は出力が FIFO のため、隙間が無音としても残らず再生が早期化する
  分だけ悪化し得る。
- qmux は原因を増幅する。QMux の DATAGRAM は TCP 1 本の順序付きストリームに載るため、
  TCP の再送待ちで音声がまとめて遅れて届く。受信バッファの上限を超えると破棄される。

## 比較して分かったこと

### 一致していた点

- 時間圧縮・補間: `src/playout/stretch.rs` と moqt-js の `audioTimeStretch.ts` は、4 kHz への
  間引き、相関窓、ピッチ探索、クロスフェード、放物線補間、継ぎ目の段差判定、末尾のフェード
  まで一致する。
- 再生スケジューラ: `src/playout/scheduler.rs` と `audioPlayout.ts` は、目標時刻の決定、
  並べすぎの判定、到着基準へのフォールバック、詰める量の式、隙間の条件が一致する。
- 遅延推定・閉ループ・追いつき: `delay.rs` / `feedback.rs` / `catch_up.rs` は、窓・分位点・
  忘却・上限・増減の速さ・床・cooldown まで一致する。
- 時間軸: `timeline.rs` と `timeline.ts` は、基準の 10 秒窓最小値、A/V 同期の不感帯、
  補償上限、ドリフト判定、減衰まで一致する。

### 移植漏れ

- 映像 jitter の 500 ms 超サンプルを分位点から除外するフィルタが無い。バーストで 500 ms を
  超える遅れが混ざると映像の表示遅れが上限に張り付き、A/V 同期が音声へ最大 100 ms を即時
  加算する。
- 基準の共有解除が古い。解除のきっかけが動きだったことを早期解除の条件にしており、往復の
  検出が無い。遅い経路で解除が戻らない、または往復して音声の目標が段差で動く。

### 出力経路の設計差

- moqt-js は Web Audio の絶対時刻 `start(when)` で予約するため、埋めなかった隙間は無音として
  時間軸に残る。moqt-rs は `raw_player` の FIFO に PCM を積むだけで PTS を再生時刻に使わない
  ため、埋めなかった隙間は後続の早期化になる。
- 現状の example は復号済みフレームを目標の 40 ms 前まで保持し、最初の 1 フレームで
  `play()` する。そのため先行バッファが蓄積されず、リリースの遅れがそのままアンダーランに
  なる。映像描画と音声の積み込みが同じスレッドで、vsync 有効の描画が音声供給を止める。
- 補間は「今回の音を積む瞬間」に生成されるため、出力リード 40 ms を超える隙間の先頭は
  埋められない。補間上限 100 ms と噛み合っていない。

### QMux 特有の増幅

- QMux の DATAGRAM は TCP のバイト列に載るため、TCP の再送待ち・映像との帯域共有で
  まとめて遅れて届く。QUIC 直接のように「落ちた datagram だけが消えて後続は届く」挙動には
  ならない。
- 受信側は未配送の DATAGRAM を 64 件 / 1 MiB に制限し、超えた分を破棄する。
- 送信側は STREAM と DATAGRAM を単一の FIFO に積むため、映像の burst の後ろに音声が並ぶ。
- moq-sub の datagram 受信タスクはバッチ処理のたびに 10 ms sleep し、メインループは 1 回に
  1 件しか音声を取り出さない。受信から再生までの遅延を増やす。

## 対策

- 再生の隙間を必ず材料化する。スケジューラは隙間の全長と補間してよい長さを分けて返し、
  呼び出し側は補間できなかった分をフェード付きの無音で埋める。隙間の前後は 2 ms で 0 に
  落として段差を消す。
- 復号した音声はその場で積み、最初の目標時刻に達してから再生を開始する。これにより目標
  遅延ぶんの先行バッファが蓄積される。映像の vsync は無効にする。
- 出力が枯れたらその量を目標遅延の閉ループへ入力する。アンダーランは事後には埋められない
  ため、目標を上げる以外に減らせない。
- 受信した音声の到着時刻と復号完了時刻をフレームへ載せ、時間軸への観測には復号完了時刻を
  使う。datagram の sleep は空バッチのときだけにし、音声は毎ループ全件取り出す。
- moqt-js の映像 jitter 上限フィルタと共有解除の往復検出を移植する。

## 検証方法

- 5 秒ごとのログで `gaps` / `gap_ms` / `underruns` / `underrun_ms` / `player_buffer_min` /
  `concealed` / `compressed` / `skew_us` を読む。`underruns` が増えるなら供給が目標遅延を
  超えて止まっている。`gaps` だけが増えるなら隙間の材料化が効いている。
- 同じ素材・同じリレーで qmux と QUIC 直接、映像あり / 映像なし、subgroup / datagram を
  比較する。qmux だけで `underruns` が増え、QMux の破棄警告が出ていなければ TCP の
  再送待ちによるバーストが原因である。
- moq-pub の `--target-latency` を 300〜500 ms にして症状が消えるかを見る。消えるなら
  遅延スパイクに対して目標遅延が不足している。
