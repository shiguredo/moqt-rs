## 目的

`src/playout/splice_fade.rs` に入れたフェードを、`examples/moq-pub` の音声の配信へ配線する。
今は配線されておらず、追いつきでチャンクを捨てた境目の波形が飛んでクリックとして聞こえる。

## 現状

- `fade_splice_edge` は `f32` のチャンネルを扱う。しかし moq-pub が符号化器 (Opus) へ渡すのは
  `i16` の PCM であり、符号化の直前で `f32` へ変換して戻すと量子化の誤差が乗る
- `examples/moq-pub/src/pipeline.rs` の音声のループは、追いつきの判定が偽ならチャンクを
  捨てる。捨てた境目の波形は繋がっていない
- フェードを掛けるには、符号化へ渡すチャンクを 1 つ保持する必要がある。捨てるかどうかは
  次のチャンクの判定を見るまで分からないためである

## 設計方針

- `src/playout/splice_fade.rs` に `fade_splice_edge_i16` を追加する。`fade_splice_edge` と
  同じ規則を 16 bit PCM に対して行い、整数のまま丸める (`f32` を経由しない)
- moq-pub の音声のループで、符号化へ渡すチャンクを 1 つ保持する。次のチャンクの判定を
  見てから、保持していたチャンクを符号化へ渡す
  - 次のチャンクが捨てられる → 保持していたチャンクの末尾を落として符号化へ渡し、
    その次に符号化するチャンクの先頭を落とす
  - 次のチャンクが符号化される → 保持していたチャンクをそのまま符号化へ渡し、新しい
    チャンクを保持する
- 先読みの分だけ符号化が 1 フレーム遅れる。配信の終了時には、保持しているチャンクを
  符号化へ渡してから閉じる (渡さないと最後の 1 フレームが送られない)
- 落とす長さは [`AUDIO_SPLICE_FADE_US`] (2 ms) のままとする
- 後方互換は不要 (破壊的変更を恐れない)

## 完了条件

- `fade_splice_edge_i16` の契約 (端が 0 になる・落とす長さの外は元の値のまま・端へ向けて
  単調に小さくなる・複数チャンネルへ同じ処理) がテストで固定されていること
- 捨てる直前のチャンクの末尾と、捨てた直後のチャンクの先頭が落ちることがコードで
  読み取れること (ループの構造として固定する)
- 配信の終了時に保持しているチャンクが符号化へ渡ることがコードで読み取れること
- E2E Test が成功すること
- `make pbt` / `make test` / `make clippy` / `make fmt` が通ること
- ソースコードに issue 番号や issue への言及を書かないこと
