# 音声と映像の共有の時間軸を追加する

- Created: 2026-10-01
- Completed: 2026-10-03
- Branch: feature/add-playout-timeline
- Polished: 2026-10-01

## 目的

同じ render group の音声と映像を同時に表示するため、LOC の TIMESTAMP を共通の軸にして表示時刻を決める。
表示時刻 = TIMESTAMP + 基準の遅れ + 表示の遅れとする。基準の遅れは受信側の壁時計と TIMESTAMP の差の直近の最小値、
表示の遅れは jitter buffer の遅延 (音声は [issues/0185](0185-add-playout-delay-and-sync.md)、映像は表示待ちの揺らぎの百分位) である。
MSF の `targetLatency` (draft-ietf-moq-msf-01 §5.2.8) を 2 つのトラックの遅れの下限にし、A/V 同期の遅延制御 ([issues/0185](0185-add-playout-delay-and-sync.md)) を 1 秒ごとに適用する。

## 現状

- `src/` に表示時刻を決める時間軸が無い
- [issues/0104](0104-add-subscriber-av-sync.md) は examples の A/V 同期を `raw_player` の音声クロックに載せる方針を検討中であり、ライブラリ側に共有の時間軸を持つ口は無い
- 映像はピクセルを扱わない。観測は「復号の出力の時刻」と「TIMESTAMP」の組だけを受け取る
- 前提: [issues/0185](0185-add-playout-delay-and-sync.md) (目標遅延と A/V 同期の遅延制御) の完了

## 設計方針

`src/playout/timeline.rs` を追加する。時刻は i64 マイクロ秒で扱い、表示時刻は壁時計のマイクロ秒で返す。デバイスの時計へ換算するのは呼び出し側とする。

### 観測

- `observe(stream, wall_clock_us, timestamp_us)` で音声と映像の復号の出力を記録する。`stream` は音声と映像の 2 値
- 音声の観測は [issues/0185](0185-add-playout-delay-and-sync.md) の目標遅延の学習へ渡す。0185 の「到着の時刻」にはこの復号の出力の時刻 (受信側の壁時計) を使う
- 映像の表示待ちのキューの上限 (枚) と、表示の遅れの上限 (既定 500 ms) を設定で受ける
- 直近のフレーム間隔 (TIMESTAMP の差の中央値、直近 32 個) を保持する
- まとまって届いた観測 (前の観測からフレーム間隔の半分未満) は揺らぎの学習に使わない

### 表示時刻

- 基準の遅れ: トラックごとの (壁時計 − TIMESTAMP) の直近 10 秒の最小値。基準は到着ではなく復号の出力の時刻で測る
- 表示の遅れ (音声): [issues/0185](0185-add-playout-delay-and-sync.md) の目標遅延
- 表示の遅れ (映像): ((壁時計 − TIMESTAMP) − 基準の遅れ) の百分位
  - 百分位は「表示時刻の後に届くフレームが 1 秒に 1 枚までになる値」とし、`max(0.95, 1 - フレーム間隔 (ms) / 1000)` で求める
  - 上限は「表示の遅れの上限 (500 ms)」と「表示待ちのキューが吸収できる長さ ((上限枚数 − 余裕 4 枚) × フレーム間隔)」の小さい方 (フレーム間隔がまだ分からないときは 500 ms、計算結果が負のときは 0 とする)
  - 目標が下がるときは 20 ms / 秒で減衰させる。上限が下がったときは上限まで直ちに下げる
  - live に追いつくまで (250 ms ごとに基準の下がり幅が 20 ms 以上ある間) は学習しない。一度追いついたら取り直すまで戻らない
- `targetLatency` (ミリ秒) は呼び出し側が設定で渡す (MSF の `MsfTrack::target_latency` の解決は呼び出し側)。値が無いときは 0 として扱う。A/V 同期の基準の遅延になり、2 つのトラックの表示の遅れの下限になる。上限に収まらず切り下げた分を読めるようにする
- スケジューラ ([issues/0186](0186-add-playout-scheduler.md)) が `presentation_delay` として使う表示の遅れ (音声) を getter で読めるようにする

### A/V 同期

- 1 秒ごとに 1 回、両方のトラックに新しい観測があるときだけ [issues/0185](0185-add-playout-delay-and-sync.md) の制御を呼ぶ
- 0185 の制御が返す各トラックの遅延の下限は、そのまま 2 つのトラックの表示の遅れの下限として保持する
- 2 つのトラックの基準の遅れの差が閾値 (表示待ちのキューが吸収できる長さ − 表示の遅れ、下限 100 ms) を超えたら、遅れている方のトラックの TIMESTAMP を使わない。表示時刻を返さず、届いた順に鳴らす経路へ委ねる。閾値の「表示の遅れ」は、上限を適用する前の 2 つのトラックの表示の遅れの大きい方を使う
- ずれているトラックがある間は 0185 の制御を呼ばない (ずれの推定が単調に増えるため)

### 取り直しと実績

- 基準との差が 2 秒以上離れたら TIMESTAMP が飛んだとみなして基準を取り直す。世代 (generation) を進め、取り直しより前に積んだフレームがあることを呼び出し側へ伝える
- 1 つのトラックだけリセットする操作と、すべてリセットする操作を分ける。基準の遅延 (`targetLatency`) は残す
- 表示した実績 (TIMESTAMP と表示時刻) を記録し、直近 1 秒以内の実績から A/V のずれを返せるようにする

### その他

- 窓は `alloc::vec::Vec` または固定リングで持つ。百分位は `slice::sort_unstable_by` と `total_cmp` (整数なら通常の比較) で求める。`floor` / `ceil` / `round` を使わない
- examples への適用は別 issue とする。ライブラリの時間軸を examples へ適用する場合は [issues/0104](0104-add-subscriber-av-sync.md) の `raw_player` 前提の方針と重なるため、0104 の扱い (維持・改訂) は適用時に決める
- `CHANGES.md` の `## develop` に `[ADD]` を追加する

## 完了条件

- TIMESTAMP + 基準の遅れ + 表示の遅れが表示時刻として返ること
- 音声の表示の遅れが [issues/0185](0185-add-playout-delay-and-sync.md) の目標遅延に追従すること。0185 の制御が返す遅延の下限が表示の遅れに反映されること
- 映像の表示の遅れが揺らぎの百分位から求まり、上限を超えないこと。目標が下がったとき 20 ms / 秒で下がること
- 追いつき中の観測が学習に使われないこと
- `targetLatency` が 2 つのトラックの表示の遅れの下限になり、切り下げた分が読めること
- スケジューラが `presentation_delay` として使う表示の遅れ (音声) が getter から読めること
- 基準との差が 2 秒以上離れたときに取り直しと世代の更新が起きること
- 基準の差が閾値を超えたとき、遅れているトラックの表示時刻が返らないこと
- A/V 同期の制御が 1 秒ごとに 1 回だけ呼ばれること
- 実績から A/V のずれが読めること
- `make test` (`cargo test --workspace`) と `make clippy` と `make fmt` が通ること
- `cargo build -p shiguredo_moqt --target thumbv7em-none-eabihf` が通ること

## 解決方法

- `src/playout/timeline.rs` を仕様どおりに実装した。表示時刻 = TIMESTAMP + 基準の遅れ (直近 10 秒の最小値) + 表示の遅れであり、音声は `playout::delay` の目標遅延、映像は揺らぎの百分位を使う
- 映像の表示の遅れは `max(0.95, 1 - フレーム間隔 (ms) / 1000)` の百分位とし、上限 (表示の遅れの上限と (キューの上限 − 余裕 4 枚) × フレーム間隔の小さい方) で切る。目標が下がるときは 20 ms / 秒で減衰させ、上限が下がったときは直ちに従う。追いつき中 (250 ms ごとの基準の下がり幅が 20 ms 以上) の観測は学習しない
- A/V 同期の制御 (`playout::sync`) を 1 秒ごとに 1 回だけ、両方のトラックに新しい観測があるときだけ呼び、返った遅延の下限を表示の遅れの下限として保持する。基準の差が閾値 (上限 − 上限適用前の表示の遅れ、下限 100 ms) を超えたら遅れているトラックの表示時刻を返さず、ずれている間は制御を呼ばない
- `targetLatency` を設定で受け、2 つのトラックの表示の遅れの下限にする (上限に収まらず切り下げた分は `limited_us` で読める)。TIMESTAMP が基準から 2 秒以上離れたら基準を取り直して世代 (`generation`) を進める。1 つのトラックだけのリセットとすべてのリセットを分けた
- 表示した実績 (TIMESTAMP と表示時刻) を記録し、直近 1 秒以内の実績から A/V のずれ (`skew_us`) を返す
- テストを `tests/test_playout/timeline.rs` (公開 API)、`pbt/tests/prop_playout/timeline.rs` (PBT)、`src/playout/timeline.rs` の単体テストに追加した。`docs/moqt.md` と `skills/shiguredo-moqt/SKILL.md` のモジュール構成と API を更新し、`CHANGES.md` に `[ADD]` を追加した
