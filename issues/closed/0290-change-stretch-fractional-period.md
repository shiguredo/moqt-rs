# 補間の周期を端数まで求め、低いピッチと雑音の誤検出を直す

- Created: 2026-10-16
- Completed: 2026-10-16
- Branch: feature/change-stretch-fractional-period
- Polished: {YYYY-MM-DD}

## 目的

moqt-js は 2026-10-16 の変更 (39d3fb7a、「playout のノイズの原因を修正し、目標遅延を経路に適応させる」) のうち `src/playout/audioTimeStretch.ts` の `concealSamples` (欠落した区間の補間) で、末尾の周期を端数まで求めるようにし、相関の窓を固定長にした。目的は 2 つある。

1 つ目は、補間の周期が 4 kHz の格子に量子化されることである。格子に乗らない 440 Hz (周期 109.09 サンプル) では、求めた周期 (108) で繰り返すため穴が長いほど位相がずれ、穴の終わりで次に鳴る音との段差が大きくなる。段差はクリックとして聞こえる。moqt-js の実測 (48 kHz、20 ms のフレーム、振幅 0.5、穴の終わりの段差 ÷ 振幅) では 20 ms で 34.4 %、40 ms で 101.8 %、100 ms で 195.1 % だった。

2 つ目は、相関の窓を候補のずらし幅に比例させていたことである。窓が短い (= ずらし幅が短い) 候補ほど相関が高く出るため、有色雑音で最短のずらし幅 (400 Hz) を選び、ブザーになる。moqt-js の実測 (40 フレーム、40 ms の穴) では補間が 5.5 % / 19.5 % のフレームで働き、最短のずらし幅を選んだフレームが 6 件あった。あわせて、窓の長さ + ずらし幅がフレーム長に収まる制約から、20 ms のフレームでは 137.9 Hz より低いピッチを探せず、100 Hz の有声は補間そのものをしなかった。

moqt-rs の `src/playout/stretch.rs` も同じ欠陥を持つ。`find_tail_lag` は末尾の 2 周期分どうしの相関を 4 kHz の格子で探すだけで、端数の詰めが無い。窓の長さは候補のずらし幅に比例し、ずらし幅は末尾の 2 周期分が取れる範囲に限られる。

## 現状

- `src/playout/stretch.rs` の `find_tail_lag` は、末尾の 2 周期分どうしの正規化相関の二乗が最も大きいずらし幅 (`usize`) を返す。`conceal` は `period = lag * 間引き率` で整数の周期にする。
- 繰り返しの生成は `source[index % period]` の整数の剰余であり、端数の位置を読めない。
- 相関の窓の長さはずらし幅に比例する (`tail[end - 2 * lag..end - lag]`)。
- ずらし幅の上限は `TIME_STRETCH_MAX_LAG.min(end / 2)` であり、20 ms のフレーム (48 kHz、4 kHz へ間引くと 79 サンプル) では 39 である。
- 継ぎ目の段差の検査 (`is_seam_smooth`) は第 1 チャンネルだけで、整数の添字で行う。
- 末尾の相関が低いときは補間をやめるだけで、生成した音の末尾をフェードしない。
- 実測 (48 kHz、20 ms のフレーム、振幅 0.5、20 ms の穴): 1000 Hz と 440 Hz は 960 サンプルを生成し、300 / 220 / 150 / 100 Hz は生成しない (格子のずれによる継ぎ目の段差が許容を超えるため)。

## 設計方針

moqt-js の最新の判定を移植する。

- 末尾の周期の探索を 2 段にする。1 段目は 4 kHz へ間引いた信号で、固定長の窓 (39 = 9.75 ms) どうしの相関が最も高いずらし幅を粗く探す。2 段目はその周辺 (±1 格子) を元のサンプルレートの相関で評価し、ピークを放物線補間して端数まで求める。
- 放物線の頂点は細探索した 3 点が揃うときだけ求める。最大が細探索の端にあるときと、上に凸でない (曲率が 0 以上) ときは格子のままにする。端で外挿すると探索の下限の外側のずらし幅を返して周期が 0.5 サンプルずれ、穴の終わりで位相が合わなくなるためである (400 Hz = 周期 120 サンプルは細探索の下限そのもので、この経路を通る。moqt-js も後続の変更 5fed7505 で同じ扱いを入れている)。
- 窓の長さは候補のずらし幅に比例させず固定にする。窓の長さ + ずらし幅が音の長さに収まる範囲でずらし幅の上限を最大化し、20 ms のフレームでは 40 (100 Hz) まで探す。
- 繰り返しの生成は、端数の位置を線形補間で読む。参照の末尾をまたぐときは 1 周期前 (周期の先頭) を続きとして読む。
- 継ぎ目の段差の検査は全チャンネルで行う (周期は第 1 チャンネルだけで決める)。
- 周期の推定が確かでない (相関が 0.95 未満) ときは、生成した音の末尾を 2 ms で 0 へ落とし、穴の終わりの段差を「無音からの立ち上がり」に変える。
- 対応外のサンプルレート、短すぎる音、相関が閾値未満の音では補間しないという既存の契約は変えない。無音に近い入力では周期の代わりに 0 を書く既存の扱いも変えない。
- Sans-I/O と no_std を維持する。時刻は引数で受け取り、ヒープ確保は増やさない。`no_std` には `f64` の `floor` / `ceil` / `round` / `sqrt` が無いため、整数への切り捨てと比較で代用し、放物線補間は正規化相関の二乗の上で行う (端数推定への影響は実測で確かめる)。
- 破壊的変更を恐れない。補間の可否と周期が変わるため、旧挙動を固定していたテストは新しい契約へ書き換える。

## 完了条件

- 末尾の周期が端数まで求まり、繰り返しが線形補間で生成されること。
- 相関の窓が固定長になり、ずらし幅の上限が 100 Hz まで広がること。
- 末尾のフェード (2 ms) と、全チャンネルの継ぎ目の検査が入ること。
- `tests/test_playout/stretch.rs` が、段差 (440 Hz の穴の終わり)、周期 (100 Hz の有声)、有色雑音と最短のずらし幅の誤検出の境界を固定していること。
- `pbt/tests/prop_playout/stretch.rs` が新しい契約に追随していること。
- `cargo test --workspace` / `cargo clippy --workspace --all-targets -- -D warnings` / `cargo fmt --all -- --check` / `cargo test -p pbt` が通ること。
- ソースコードに issue 番号や issue への言及を書かないこと。

## 解決方法

- `src/playout/stretch.rs` の `find_tail_lag` を `find_tail_period` に置き換えた。4 kHz へ間引いた信号で固定長の窓 (新定数 `TIME_STRETCH_TAIL_CORRELATION_LEN` = 39) どうしの相関が最も高いずらし幅を粗く探し、その周辺 (±1 格子) を元のサンプルレートの相関で評価して、ピークを放物線補間して端数まで求める。ずらし幅の上限は `min(TIME_STRETCH_MAX_LAG, 間引き後の長さ - 窓の長さ)` であり、20 ms のフレームでは 40 (100 Hz) になる。
- 相関は正規化相関の二乗 (`dot * dot / (energy_before * energy_after)`) で持ち、`no_std` に `f64::sqrt`
  が無いため平方根を取らない。閾値との比較も二乗のまま行う。放物線補間はこの二乗の上で行う (moqt-js
  は正規化相関の上で行うが、実測では 440 Hz の段差が 4.7 / 4.5 / 1.6 %、200 Hz が 2.6 %
  と一致し、求める周期の差も 1e-3 サンプル以下であるため、平方根を持ち込まない)。頂点を求める 3
  点のうち隣が正の相関にならない (逆向きの波形、振幅が無い) ときは候補から外れるため、その値は 0 として扱う
  (moqt-js は符号付きの正規化相関をそのまま使うため、この置き換えは moqt-rs
  独自の扱いである。ずらし幅そのものの選択は変わらない)。
- 放物線の頂点は細探索した 3 点から求めるため、最大が細探索の端にあるときは求められない。端では格子のままにする (端で外挿すると探索の下限の外側のずらし幅を返し、周期が 0.5 サンプルずれる)。上に凸でない (曲率が 0 以上) ときも格子のままにする。400 Hz の周期 120 サンプルは細探索の下限そのものであり、この経路を通る (moqt-js も同じ修正を後続の変更で入れており、そちらに合わせた。moqt-js の実測では穴 100 ms の段差が振幅の 85.2 % になっていた)。
- 逆向きの波形 (相関が負) と振幅の無い区間は周期の候補から除く。moqt-js は負の相関も含めて最大を選ぶが、非無音の入力では閾値 (0.9) で落ちるため判定は変わらない (無音は先に 0 で埋める既存の扱いのまま)。
- 端数の位置は `sample_at` で線形補間して読み、`read_repeated` が末尾の周期 1 つ分の繰り返しを読む。参照の末尾をまたぐときは 1 周期前 (周期の先頭) を続きとして読む。`no_std` に `f64::floor` が無いため、0 以上の値では整数への切り捨てを小数点以下の切り捨てとして使う。
- 継ぎ目の段差の検査 (`is_seam_smooth`) を全チャンネルに広げた。1 周期前のサンプルは端数の周期に合わせて線形補間で読む。`f64::ceil` が無いため `ceil_to_usize` を足した。
- 周期の推定が確かでない (相関の二乗が `TIME_STRETCH_CONCEAL_FADE_CORRELATION` の 0.95 未満) ときは、生成した音の末尾を `TIME_STRETCH_CONCEAL_FADE_MS` の 2 ms で 0 へ落とす。長さは `sample_rate` から求める (0.5 を足して切り捨てることで四捨五入する)。
- テスト: `tests/test_playout/stretch.rs` に、格子に乗らない純音 (1000 / 440 / 300 / 220 / 150 / 100 Hz)
  を補間することを固定するテスト、440 Hz の穴の終わりの段差 (20 / 40 / 100 ms) と 200 Hz
  の段差を固定するテスト、100 / 120 Hz の有声が本当の周期 (480 / 400) で繰り返し 396
  では繰り返さないことを固定するテスト、有色雑音 (係数 0.99 / 0.999) で最短のずらし幅 (120)
  を選ばないことを固定するテスト、周期の推定が確かでない音の末尾が 0
  になりきれいな純音ではフェードしないことを固定するテスト、第 2
  チャンネルの継ぎ目の段差で補間しないことを固定するテスト、400 Hz (周期 120 = 細探索の下限) で周期が 120
  のままになり 120 サンプルで繰り返すことを固定するテストを追加した。旧挙動
  (格子に乗らない音は補間しない、整数の周期で繰り返す) を固定していた 6 件は新しい契約へ書き換えた。
- テスト: `pbt/tests/prop_playout/stretch.rs` に、探索の範囲にある周期 (120 / 160 / 240 / 320 / 480) の矩形波が補間され、生成した音が元の振幅を超えず、段差が元の最大段差の 2 倍以下になることを検証する property を追加した。
- 検証: `cargo test --workspace` (moq-sub の 18 件を含む全ターゲット)、`cargo test -p pbt`
  が成功した。`tests/test_playout/stretch.rs` は 42 件、`pbt/tests/prop_playout/stretch.rs` は 5 件
  (`PBT_SEED` を 1 / 3 / 5 / 7 / 11 に変えても成功)。`src/playout/stretch.rs` の `#[cfg(test)]` は 2
  件。`examples/moq-sub/src/main.rs` の `conceal_gap_repeats_the_previous_tail` (400 Hz の音を 120
  サンプル周期で繰り返すことを確かめる) は、放物線の端の扱いを直したことで修正なしに成功した。
- 検証: カバレッジ (`cargo llvm-cov --no-report -p shiguredo_moqt --test test_playout` と `-p pbt --test prop_playout` をマージ) は `src/playout/stretch.rs` が領域 99.10 % / 行 97.58 %。未カバーの 12 行は、いずれも短すぎる音や正の相関が取れないときの防御的な早期 return (moqt-js と同じ位置に同じ意図で置いている) である。
