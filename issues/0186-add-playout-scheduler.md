## 目的

復号した音声を届いたその場で鳴らすと、到着の間隔の揺らぎで前の音と重なったり、隙間が空いたりする。鳴らす時刻を決めるスケジューラを追加し、目標の時刻に従って並べる。目標に間に合わない音も捨てずに、今から鳴らせる最も早い時刻へずらして鳴らし、ずらした分を時間圧縮 ([issues/0184](0184-add-playout-time-stretch.md)) で目標へ戻す。再生で起きたこと (基準の取り直し、捨てた音、詰めた長さ、遅れ) を統計として読めるようにする。

## 現状

- `src/` に鳴らす時刻を決める実装が無い
- `examples/moq-sub` は復号した音声を `raw_player::AudioPlayer` へ渡しており、鳴らす時刻を決めていない
- 前提: [issues/0184](0184-add-playout-time-stretch.md) (時間圧縮・伸長) と [issues/0185](0185-add-playout-delay-and-sync.md) (目標遅延) の完了
- moqt-rs は Sans-I/O が規約であり、時刻は引数で受け、戻り値は命令とする。デバイス API・タイマー・スレッドに触れない。`core` に無い浮動小数メソッドは使えない

## 設計方針

`src/playout/scheduler.rs` を追加する。時刻は i64 マイクロ秒で扱う。呼び出し側は次の入力 (すべて i64 マイクロ秒。`now` と `target_start` は同じ再生軸、`timestamp` は TIMESTAMP 軸) を渡し、`Play { start_at, compress }` または `Drop` を返す。デバイス API やタイマーには触れない。

### 入力

- `now`: 今の時刻 (`start_at` と同じ軸のマイクロ秒)
- `timestamp`: 音の TIMESTAMP (マイクロ秒)
- `duration`: 音の長さ (マイクロ秒)
- `target_start`: 目標の開始時刻 (マイクロ秒)。無いこともある
- `enforce_target`: 目標を守るか
- `delay`: 再生の遅れ (マイクロ秒)。揺らぎから求めた音声の遅れ ([issues/0185](0185-add-playout-delay-and-sync.md) の目標遅延) であり、まだ観測が無いときは下限の 80 ms を使う
- `presentation_delay`: 表示の遅れ (マイクロ秒)。表示時刻に使う遅れで、自分の揺らぎ、`targetLatency`、A/V 同期の下限の大きい方を上限で切った値。時間軸 ([issues/0187](0187-add-playout-timeline.md)) が渡す

`target_start` が無い、または `enforce_target` が false のときは到着基準の並べ方を使う。

### 目標があるとき (`target_start` があり `enforce_target` が true)

- 鳴らす時刻は `max(target_start, max(now + 下限 10 ms, 前の音の終わり))` とする。目標に間に合うときは目標の開始時刻になる
- 並べすぎ (`target_start` > `now` + `max(delay, presentation_delay)` + 余裕 220 ms) は捨てる
- 目標を過ぎて届いた音も前の音と重なる音も捨てず、ずらして鳴らす (`now + 下限 10 ms` と前の音の終わりの遅い方)
- 目標から 500 ms を超えて離れた音は捨てて目標へ戻す (経路の停止からの回復)
- ずらした分 (遅れ = 鳴らす時刻 − `target_start`) を時間圧縮で戻す。1 つの音で詰める量は「遅れ」と「音の長さの半分」の小さい方とする
- ずれは前の音から引き継いだ分を含む「今の音のずれ」であり、積み上げない。詰めた分は前の音の終わりが早くなることで次の音へ引き継がれる
- 実際に詰めた量は `confirm_stretch` で受け取る。要求より少ないときは、詰められなかった分だけ音が後ろへ伸び、遅れとして残る
- 音を予約する前に前回の `confirm_stretch` が来ていなければ、適用されなかったものとして扱う

### 目標が無いとき、または守らないとき (到着基準)

- 最初の音で基準 (今 + `delay`) を決め、TIMESTAMP の間隔どおりに並べる
- 鳴らす時刻は「基準の時刻 + (TIMESTAMP − 基準の TIMESTAMP)」とし、前の音の終わりより前にはしない
- 鳴らす時刻が `now + 下限 10 ms` より前になるときは、基準を取り直して `now + delay` に鳴らす (前の音はすべて今より前に終わっているため重ならない)
- 鳴らす時刻が `now + delay + 余裕 220 ms` より後になるときは、`max(now + delay, 前の音の終わり)` を候補にする。候補が上限を超えるなら捨て、超えないなら候補へ並べ直して基準を取り直す
- TIMESTAMP の間隔が音の長さと同じときも、前の音の終わりに繋げて鳴らし、音を欠かさない

### 定数

- 再生の遅れの下限: 80 ms (時間軸がまだ音声を観測していないときに使う)
- 並べすぎの余裕: 220 ms。上限は `max(delay, presentation_delay) + 220 ms` であり、どちらも 80 ms のとき 300 ms になる
- 鳴らす時刻の下限 (今からの余裕): 10 ms
- 目標から離れすぎとみなす量: 500 ms

### 統計

- 累積統計 (基準の取り直し回数 / 捨てた音の数 / 詰めた合計 (マイクロ秒)) と、現在値 (目標からの遅れ (マイクロ秒)) を getter で読めるようにする
- 基準の取り直し (`reset`) は基準と前の音の終わりと現在の遅れを消し、累積統計は消さない。累積統計を消す操作 (`reset_stats`) を別に用意する

### その他

- 隙間の補間 (欠落した区間を直前の音の末尾から伸ばして埋める) は後続の issue とする
- `CHANGES.md` の `## develop` に `[ADD]` を追加する

## 完了条件

- 目標を過ぎて届いた音と前の音と重なる音が捨てられず、ずらして鳴り、詰めた分だけ遅れが減って目標へ戻ること
- 目標に間に合う音は目標の開始時刻に鳴ること。目標より前に鳴らないこと
- TIMESTAMP の間隔と音の長さが同じ入力で音が欠けないこと
- 並べすぎの音と、目標から 500 ms を超えた音が捨てられること
- 到着基準で、過ぎて届いた音のときに基準が取り直され、大きく飛んだときに並べ直されること。並べ直しても上限を超える音は捨てられること
- `confirm_stretch` が要求より少ないとき、その分の遅れが残り、次の音の開始時刻へ反映されること
- 統計 (取り直し / 捨てた数 / 詰めた合計 / 遅れ) が実測と一致すること。`reset` で累積統計が消えず、`reset_stats` で消えること
- `make test` (`cargo test --workspace`) と `make clippy` と `make fmt` が通ること
- `cargo build -p shiguredo_moqt --target thumbv7em-none-eabihf` が通ること
