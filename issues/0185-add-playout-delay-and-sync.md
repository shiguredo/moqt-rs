## 目的

音声の再生では、経路の揺らぎに応じた jitter buffer の遅延 (目標遅延) を決める必要がある。固定値では、揺らぎが小さいときに余計に遅れ、大きいときに音が途切れる。到着の遅れの分布から「途切れの確率が一定以下になる遅延」を求める。

また、音声と映像の遅延の差を制御して A/V のずれを抑える。ずれの推定を平滑化し、不感帯を置き、片側だけを上限付きで動かす。

## 現状

- `src/` に音声の jitter buffer の遅延を決める実装が無い
- [issues/0104](0104-add-subscriber-av-sync.md) は examples の A/V 同期を `raw_player` の音声クロックに載せる方針を検討中であり、ライブラリ側で遅延を決める口は無い
- moqt-rs は `#![no_std]` + `alloc` であり、`core` に無い浮動小数メソッド (`floor` / `ceil` / `round` / `trunc` / `sqrt` / `powf` など) は使えない

## 設計方針

`src/playout/delay.rs` (目標遅延) と `src/playout/sync.rs` (A/V 同期の遅延制御) を追加する。時刻は i64 マイクロ秒で受け、遅延・相対遅延・ずれ・閾値はミリ秒 (i64) で扱う。マイクロ秒で受けた時刻の差は 1000 で割り、0 方向への切り捨てでミリ秒へ換算する。デバイス API やタイマーには触れない。

### 目標遅延 (delay.rs)

- 到着の観測は「到着の時刻」と「そのデータの TIMESTAMP」の組で受け取る
- 到着の遅れは、直近 2 秒の窓で「到着 − TIMESTAMP」が最小の観測を基準にした相対値とする。送信側と受信側の時計のずれと経路の最小遅延は基準に含まれ、引き算で消える
- 相対値は 500 ms ごとに 1 つだけ、区間の最大値をヒストグラムへ入れる。揺らぎの尾を遅延へ反映させるため、平均ではなく区間の最大を使う
- バケット番号は `切り捨て(相対値 (ミリ秒) / 20)` とし、0 未満または 100 以上は捨てる
- ヒストグラムは 20 ms ごとの 100 バケット (0 から 2000 ms) とする
  - 初期分布は `0.5^(i + 1)` (反復または定数表で作る。`powf` は core に無い)
  - 追加のたびに全体を forget factor 倍し、観測したバケットへ `1 - forget factor` を足す
  - forget factor は 0 から始め、追加のたびに `max(0, min(0.983, 1 - 2 / (追加回数 + 1)))` とする (追加回数は 1 始まり。最初の数回だけ 0.983 より小さく、すぐ収束する)
- 目標遅延は 0.95 分位のバケットから `(バケット + 1) * 20 ms` とする。観測が無いときは 80 ms
- 窓より古い観測は捨てる。窓は `VecDeque` または固定リングで持ち、メモリが増え続けないようにする
- ヒストグラムは `[f64; 100]` の固定長で持てる。`reset` で初期状態へ戻す

### A/V 同期の遅延制御 (sync.rs)

- 相対遅延 (ミリ秒) と、現在の音声の遅延と映像の遅延 (どちらもミリ秒) を呼び出しごとに引数で受け取る。遅延の値は呼び出し側 (時間軸) が渡す
- 相対遅延 = 映像の受信時刻 − 音声の受信時刻 − (映像の TIMESTAMP − 音声の TIMESTAMP)。絶対値が 10 秒を超えるときは制御しない
- ずれ = 映像の遅延 − 音声の遅延 + 相対遅延。平均は `切り捨て((3 * 平均 + ずれ) / 4)` で更新する (単純な移動平均ではない)
- 平均の絶対値が 30 ms 未満の間は何もしない。この不感帯の間、映像は音声より最大 30 ms 先行してよい
- 1 回に動かす量は平均の半分を ±80 ms で切った値とする。動かしたら平均を 0 に戻す (行き過ぎない)
- 動かすのは片側だけとする。映像の余分な遅延を削るか音声を遅らせる (逆も同じ)。映像の遅延は基準の遅延を下回らない
- 返す値は基準の遅延から 10 秒以内に切る
- 呼び出しは 1 秒ごとに 1 回。基準の遅延 (MSF の `targetLatency` に相当) は `set_target_buffering_delay` で受け取る

## 完了条件

- ヒストグラムへ 1 つも追加していない間は目標遅延が 80 ms のまま。揺らぎの無い観測では分位点の最小値 (20 ms) になり、揺らぎを加えると分位点に応じた値 (20 ms から 2000 ms) へ上がること
- 500 ms の区間の中間の観測が学習に使われず、区間の最大値だけが使われること
- 揺らぎが減ると forget factor により目標遅延が下がること
- 目標遅延が、ヒストグラムへ追加する前は 80 ms、追加後は 0.95 分位の期待値 (バケット 0 なら 20 ms) になること
- 窓より古い観測が捨てられ、メモリが増え続けないこと
- 相対遅延が ±10 秒を超えるときは制御されないこと
- 不感帯 (30 ms) の中では遅延が変わらないこと
- 1 回の制御で動く量が ±80 ms を超えないこと。動かしたら平均が 0 に戻ること
- 音声と映像のどちらか片側だけが動くこと。映像の遅延が基準を下回らないこと
- `make test` (`cargo test --workspace`) と `make clippy` と `make fmt` が通ること
- `cargo build -p shiguredo_moqt --target thumbv7em-none-eabihf` が通ること
